# Samewhere

Первый браузерный прототип пространственной головоломки. Семь логических комнат, четыре шара и проходы, которые можно соединять между собой. Three.js + TypeScript + Vite; геометрия и звуки создаются программно, текстуры загружаются из локальных файлов. Внешних моделей и шрифтов нет.

Визуальный стиль — Backrooms по предоставленным референсам: жёлтые обои с мелким узором, бежевый ковролин, подвесной потолок с сеткой 65 × 65 см и прямоугольные люминесцентные панели. Геометрия остаётся простой, без направляющих меток на стенах и пьедесталах. Ближние комнаты не покрываются туманом или цветовым фильтром. Дальние комнаты плавно темнеют на расстоянии 48–68 м, сохраняя оттенки до исчезновения. Свет создаёт контраст и тёплую палитру самого окружения; фон меню не растушёвывает сцену.

Текстуры обоев, ковролина, литого бетона пьедесталов и минеральных потолочных панелей созданы для Samewhere встроенным `image_gen`; тонкая Т-образная сетка потолка добавляется кодом. Точные запросы генерации и масштаб материалов сохранены в [источниках материалов](public/materials/sources.json). Игра не обращается к внешним сервисам.

## Запуск

Нужен Node.js 22.12+ и настольный браузер с WebGL 2.

```sh
npm install
npm run dev
```

Откройте адрес Vite (обычно http://127.0.0.1:5173/) и нажмите «Войти в пространство». Если встроенный предпросмотр запрещает захват мыши, откройте адрес в отдельной вкладке Chrome, Edge или Firefox.

```sh
npm test          # правила, преобразования, коллизии, отмена
npm run build    # проверка TypeScript и production-сборка в dist/
npm run preview  # локальный просмотр production-сборки
npm run test:browser # браузерные приёмочные проверки
npm run profile   # замер быстрых поворотов в Chrome; Vite должен быть запущен
npm run profile:pacing # Chrome с окном, GPU-замеры и трасса показа кадров
npm run profile:interactions # сравнение нагрузки при действиях с шарами и ходьбе
npm run profile:lighting # GPU/CPU с переносом света и без него в одинаковых сценах
npm run profile:hub # первое открытие прохода в H и реальный переход в хаб
```

Браузерные тесты используют установленный Google Chrome через Playwright и сами запускают Vite, если сервер ещё не работает. Они сохраняют снимки в `test-results/`. Для другого браузера измените `channel` в `playwright.config.ts`.

Свет панелей, одно отражение от пола и стен и подсветка всех возможных проходов рассчитываются в Node.js при сборке. Браузер загружает готовый бинарный файл и подготавливает GPU; расчёта света на CPU при запуске игры нет. Vite автоматически перегенерирует файл при изменении уровня, света, алгоритма или его зависимостей. При локальной разработке такие изменения дожидаются нового файла и полностью перезагружают игру. Неизменившиеся данные берутся из кэша `node_modules/.cache/samewhere-lighting/`; отдельную команду запекания запускать не нужно.

`npm run dev` использует быстрый черновой расчёт света, `npm run build` — полный точный расчёт. Для них создаются отдельные файлы и кэши. Тонкие полосы и границы теней проверяйте через `npm run build` и `npm run preview`.

Прямой запечённый свет местных панелей и отражённый свет хранят производную освещённости по наклону нормали, включая отражения через порталы. Она вычисляется из того же интеграла источников, что и яркость, с отсечением по горизонту поверхности. Шейдер использует линейное приближение для реакции на карту нормалей; при нулевой силе нормалей сохраняется исходная яркость. Микротени не моделируются. Локальные карты содержат три RGBA-плоскости (яркость, производную отражения и производную прямого света), карты отражений через порталы — две. Плоскости упакованы в одну текстуру, чтобы не увеличивать число GPU-сэмплеров в хабе с семью источниками. Кэшированный прямой свет соседних комнат пока использует геометрическую нормаль.

## Управление

| Клавиша | Действие |
| --- | --- |
| WASD, стрелки | Движение |
| Мышь | Обзор |
| ЛКМ по лунке | Забрать шар / положить выбранный |
| 1 / 2 | Выбрать красный / синий |
| Z | Отменить подбор, размещение или переход |
| R | Начать заново |
| Esc | Пауза и освобождение мыши |
| F | Включить / выключить полноэкранный режим |
| F3 | Отладка, FPS и ресурсы |
| F4 | Шестисекундный тест плавности: камера движется автоматически, повторное нажатие останавливает тест |
| Tab | Отладочное перемещение по комнатам: хаб H → A → B → C → D → E → F → хаб; после сброса первый переход снова в хаб |
| 0 / Num0 | Подготовка проверки галереи: квадратная комната с четырьмя символами, все шары в руках; Z отменяет переход |
| 9 / Num9 | Последняя комната галереи перед белым пространством, взгляд на EXIT; шары расставлены, маршрут активен; Z отменяет переход |
| M | Включить / выключить звук |

Подойдите к пьедесталу и посмотрите вниз на шар или лунку: при доступном взаимодействии точка прицела немного увеличивается. Дальность взаимодействия — 2,25 м. Все лунки доступны с одной стороны пульта. Занятая лунка всегда отдаёт шар, без автоматического обмена.

В обычной игре видны только маленькая точка прицела и шары в руках у нижнего края экрана: один цветной кружок на каждый шар, выбранный цвет чуть крупнее, центры всех кружков лежат на одной горизонтали. Пустой инвентарь полностью исчезает. Клавиши 1/2 выбирают только доступный цвет; после размещения последнего шара выбранного цвета автоматически выбирается оставшийся. Панелей, числовых счётчиков и текстовых подсказок во время игры нет. Управление доступно в меню паузы.

F3 открывает диагностику: FPS, время кадра, p95 интервалов между вызовами игрового цикла, время CPU, число долгих кадров и очередь GPU-измерений. FPS измеряет вызовы JavaScript и сам по себе не гарантирует, что браузер показал каждый кадр на мониторе. GPU замеряется асинхронно через `EXT_disjoint_timer_query_webgl2`, один замер на четыре кадра, не более восьми ожидающих запросов. При отсутствии расширения показывается прочерк. Ожидания результата GPU и `gl.finish()` в игровом цикле нет. При возврате из фоновой вкладки окно CPU-измерений сбрасывается. Для мыши запрашивается raw input без системного ускорения; если браузер возвращает `NotSupportedError`, используется обычный захват мыши.

F4 на шесть секунд равномерно ведёт взгляд по кругу без событий мыши, затем возвращает исходное направление. Позиция и шары сохраняются, ходьба и взаимодействие во время проверки приостановлены. Это позволяет отличить проблему ввода от проблемы рендера или показа кадра. Повторное F4, Esc, сброс и отмена прекращают проверку.

Обзор использует `pointerrawupdate` с отдельными отсчётами из `getCoalescedEvents()`; при отсутствии поддержки — `mousemove`. Одновременно слушается только один поток. По умолчанию все полученные движения применяются перед ближайшим кадром, без дополнительного буфера. Чувствительность — 0,002 радиана на единицу движения.

Сглаживания, интерполяции и инерции после остановки нет. Пауза, сброс, отмена и F4 очищают накопленное движение. При переходе через портал оставшееся относительное движение применяется к уже преобразованному направлению.

## Правила

Форма пульта соответствует управляемой комнате. Каждый пульт показывает общее состояние этой комнаты, где бы игрок ни находился. В A–D лунки соответствуют стенам многоугольника; в E–G — торцам коридоров. Первый рисунок находится в хабе.

| Комната | Пьедесталы |
| --- | --- |
| A — квадратная | A и B |
| B — пятиугольная | C |
| C — шестиугольная | D |
| D — треугольная | A и E |
| E — Y: три равных коридора | B и F |
| F — +: четыре равных коридора | G |
| G — H: хаб, два параллельных коридора с перемычкой | Все семь: A, B, C, D, E, F и G |

Два размещённых шара одного цвета соединяют две соответствующие стены. Если один из них находится в инвентаре, оба прохода этой пары исчезают и становятся обычными стенами. Соединять можно разные комнаты или разные стены одной комнаты.

Игрок начинает в A с пустым инвентарём. Оба красных шара установлены на пятиугольном пульте B и соединяют B0–B2. Оба синих находятся на шестиугольном пульте C, доступном в комнате B, и соединяют C0–C3. Все копии пультов показывают эти же шары. В A и D проходов сначала нет. Можно свободно исследовать пространство и перестраивать связи.

Красный пятиугольник с самого начала нарисован маркером сбоку от южного прохода левого коридора H (G3, четвёртая лунка). Дальше рисунки ведут по цепочке: G3 → B красным, B2 → D синим, D1 → A красным. Нумерация выходов здесь начинается с нуля. Вход целевой комнаты может быть любым. Достаточно открыть нужное соединение: следующий рисунок появляется сразу, без обязательного перехода. Рисунки остаются видны при открытом проёме и после перестановки шаров. Остальные соединения работают как обычно.

После открытия последнего соединения в квадратной комнате одновременно появляются четыре рисунка самой квадратной: красные у A0/A2, синие у A1/A3. Этап засчитывается, когда игрок находится в A и все четыре шара одновременно стоят на отмеченных лунках её пульта, образуя две связи комнаты с самой собой для бесконечной галереи. Управление после этого сохраняется. Прогресс входит в отмену действий и сбрасывается вместе с игрой; рисунок в хабе остаётся.

При сборке галереи сразу появляются зелёные таблички Exit по заранее заданному маршруту, независимо от положения и взгляда игрока. Первая находится над южным выходом A2. Маршрут состоит из 42 переходов от исходной комнаты и повторяет схему с короткой диагональю в начале, длинной в середине и большим обходом после неё. Последние 17 переходов идут прямо до выхода в белое пространство. Схема повёрнута по часовой стрелке на 90°, чтобы длинная диагональ из 8 переходов шла на северо-восток: красный проход слева чередуется с синим справа в каждой следующей комнате. Этот участок можно пройти прямо по диагонали, не меняя направления взгляда. Маршрут не пересекает себя и не требует разворотов обратно во вход. Геометрия комнаты остаётся общей, но переходы ведут по целочисленным координатам галереи: в каждом рекурсивном виде показывается табличка именно этого участка. Указатели остаются на своих местах при возвращении и подходе другим путём. Отмена восстанавливает положение и маршрут, сброс убирает галерею. При разборе двух петель таблички исчезают; повторная сборка начинает тот же маршрут сначала. Последний отмеченный проход ведёт сразу в пустое белое пространство без дополнительных источников света. На последних семи метрах изображение плавно переходит в белизну, достигая её у порога; при отступлении эффект ослабевает. Можно свободно ходить, обернуться и вернуться через тот же проём. Переход и возвращение входят в историю отмены; экрана завершения пока нет.

После D доступен участок E–F–G. В B–F нет собственного пульта: для переноса шаров приходится использовать управление из других комнат. До G нельзя добраться, совершая все переходы через A; придётся изменить обе исходные связи и подготовить новую опорную комнату. Это проверяется перебором доступных действий. В H находится хаб со всеми семью пультами: A, B и C стоят в левом коридоре с шагом 4,2 м, D, E и F — в правом, собственный пульт H — в центре перемычки. Между пультами и по обеим сторонам центрального пульта остаётся место для ходьбы. Все копии показывают общее состояние соответствующих комнат и позволяют перестраивать связи из хаба.

Ширина новых коридоров — 3,4 м. В Y и + торцы находятся в 7 м от центра; в H две ветви длиной 14 м соединены центральной перемычкой. Проходы находятся только в торцах: три у Y, четыре у + и четыре у H. У H учитывается боковое смещение каждого входа. Пульты повторяют весь контур комнаты, включая вырезы, и имеют лунки у концов ветвей. Над каждым пультом расположен отдельный потолочный светильник.

## Устройство прототипа

- `src/world.ts` — конфигурации комнат, четыре уникальных шара, производные связи, снимки истории, движение и коллизии. Этот модуль не зависит от Three.js, DOM или WebGL.
- `src/geometry.ts` — контуры комнат, стеновые сегменты, отступы и проверки попадания в многоугольник; используется геометрией, миниатюрами и коллизиями.
- `src/shadows.ts` — подготовленная геометрия теней и выборочный пересчёт затронутых источников света.
- `src/light-transfer.ts` — загрузка и переключение готовых карт подсветки поверхностей.
- `src/lighting-data.ts` — бинарный формат карт с проверкой версии исходников, размеров и полноты соединений.
- `scripts/bake-lighting.ts`, `scripts/lighting-plugin.ts` — генерация, кэш, отслеживание зависимостей и сжатая отдача данных через Vite.
- `src/room-visual.ts`, `src/lightmap-layout.ts` — общая геометрия для рендера и расчёта, развёртка поверхностей в атласы.
- `src/portal-surfaces.ts` — запас покрытия откосов при сглаживании без изменения физической геометрии.
- `src/lightmap-filter.ts` — плавная кубическая реконструкция освещения пола без увеличения карт.
- `src/light-transfer-sampling.ts`, `src/surface-lightmap.ts` — проверка видимости источников через проём и расчёт освещения текселей.
- `src/light-transfer-bake.ts` — подготовка всех карт в Node.js при сборке.
- `src/lighting.ts` — общие параметры потолочных источников.
- `src/white-space.ts` — пустое белое пространство с видом обратно в галерею.
- `src/scene.ts` — семь постоянных сцен, программная геометрия, общие материалы, выбор лунок лучом и рекурсивный рендер.
- `src/materials.ts`, `src/material-detail.ts` — материалы, оценка нормалей и шероховатости, физический масштаб текстур.
- `src/contact-shading.ts` — общий профиль контактного затенения и стыки стен с учётом открытых проходов.
- `src/panel-light-bake.ts` — площадной свет существующих панелей и одно рассеянное отражение.
- `src/bounce-area.ts` — конечная площадь отражателей и консервативные проверки видимости.
- `src/bounce-floor.ts` — ячейки отражающего пола, обрезанные по точному контуру комнаты.
- `src/room-environment.ts` — общая карта мягких отражений, подготовленная при загрузке.
- `src/main.ts` — цикл игры, захват мыши, HUD и клавиши.
- `src/audio.ts` — короткие синтезированные звуки через Web Audio.
- `src/timing.ts` — ограниченное окно измерений времени кадров и работы CPU.
- `src/gpu-timing.ts` — неблокирующие измерения времени GPU.
- `tests/world.test.ts`, `tests/layout.test.ts` и `tests/browser/game.spec.ts` — автоматические проверки.
- `docs/design-brief.txt` — исходный дизайн-документ.

### Вид через проходы

Каждый активный проём — поверхность с проективной выборкой изображения принимающей комнаты. Камера для этого изображения получается из исходной камеры преобразованием между системами координат проходов и поворотом на 180°. При пересечении плоскости игрок получает ровно такое же преобразование; боковое смещение, наклон и направление движения сохраняются.

Толщина стен — **0,30 м**. Внутренние грани стен остаются на апофеме комнаты 5 м, закрытая стена продолжается наружу ещё на 0,30 м. Плоскость перехода проходит посередине толщины, на расстоянии 5,15 м от центра. У открытой стены каждая сцена рисует только свою половину толщины до плоскости перехода. При соединении стен эти половины стыкуются без наложения: от внутренней грани одной комнаты до внутренней грани другой игрок проходит ровно 30 см. У проёмов есть боковые и верхний откосы; каждая половина открытой стены создаётся цельной экструдированной геометрией, без накладной рамы. На полу проёма — общий нейтральный порог: его поверхность остаётся непрерывной при любых поворотах и сочетаниях комнат.

Изображения соседей рассчитываются рекурсивно снизу вверх. Плоскость отсечения в координатах комнаты удаляет геометрию перед принимающим проёмом. Камера сохраняет обычную перспективную проекцию и распределение глубины: близость к порталу не вызывает потери точности и мерцания тонких поверхностей. Разные ветви рисуются в отдельных буферах и видны только на поверхности своего проёма: физические копии комнат не пересекаются и не просвечивают сквозь стены. Для поверхности непосредственно перед игроком отдельно сохраняется корректная глубина фрагмента, чтобы обычная ближняя плоскость камеры не вызывала вспышку перед переходом. В пределах 0,1 мм от границы проекция проёма стабилизируется отдельно, включая положение непосредственно на плоскости; это устраняет исчезающие части изображения и полосы на краях кадра.

Зона видимости — **48 м**; начиная с **28 м** поверхности плавно затухают до чёрного в линейном цвете. Это примерно две дальние комнаты; вместе с увеличенной дальностью появляется ещё около одной комнаты относительно прежнего предела. Коэффициент зависит от расстояния до фрагмента в преобразованной камере, поэтому движение и пересечение портала не меняют его скачком. Повторное затемнение поверх изображения портала не применяется.

Проёмы за 68 м не требуют дочернего рендера. Защитный предел рекурсии — 10 переходов, бюджет — **32 прохода вместе с основным**. Короткие пути через соседние стены могут содержать больше комнат, поэтому геометрическая глубина выше числа комнат в прямом коридоре. Проём непосредственно у глаз не расходует уровень. Соседи отсекаются по ориентации, экранным границам и унаследованной области видимости. Если весь проём закрыт одной непрозрачной стеной, дочерний вид также пропускается; у открытых проходов учитываются только боковые участки стены. Это сокращает скрытые рендеры за поворотами Y, + и H. Пул содержит максимум 31 переиспользуемый render target. На пределе используется чёрный цвет, скрытый дальним затуханием; сцены и геометрия при переходах не создаются заново.

Плотность пикселей в порталах совпадает с основным WebGL-холстом, включая DPR (общий предел DPR — 1,5). Прежнего ограничения ширины буферов в 1200 пикселей нет. На всех уровнях рекурсии используется то же число MSAA-отсчётов, что у основной картинки. Текстура считывается пиксель в пиксель без увеличения или размытия. Отсечение стен и потолка сохраняет покрытие половины экранного пикселя у плоскости прохода и учитывает погрешность координат: оно не удаляет целиком фрагмент, часть MSAA-отсчётов которого принадлежит откосу. Крайние вершины откосов дополнительно продолжаются на 5 см только в шейдере изображения, чтобы MSAA не примешивало тёмный скрытый торец стены. UV текстуры и карты света экстраполируются вместе с поверхностью; физическая геометрия, коллизии и карты теней сохраняют толщину 30 см. Новых треугольников и проходов рендера нет. Браузерные проверки меняют угол и субпиксельное положение верхнего стыка и отдельно проверяют боковые откосы с настоящим PBR-освещением.

Буферы соседей хранят только экранную область соответствующего проёма с запасом в два пикселя. Полная проекция сохраняется, а viewport сдвигается в обрезанную текстуру; шейдер учитывает смещение родительского и дочернего буферов. Очистка, рисование и разрешение MSAA ограничены `scissor`. Размеры выделяются блоками по 128 пикселей, растут по мере необходимости и сохраняются при ходьбе и поворотах. До игры выделяются один полноэкранный буфер и пять меньших; при изменении размера окна размеры пересчитываются. Глубина не копируется после MSAA, поскольку дальше нужна только цветная текстура. Матрицы переходов пересчитываются при изменении связей, рабочие векторы и списки рекурсии переиспользуются. Глубина порталов записывается раньше материалов комнаты, чтобы скрытые за проёмом поверхности не проходили дорогое PBR-затенение. Подсказки HUD обновляются только при изменении текста.

Основной WebGL 2 контекст создаётся явно с `alpha: false`. Панели HUD имеют непрозрачный фон и не используют `backdrop-filter`, чтобы браузеру не приходилось размывать движущийся WebGL-холст под интерфейсом.

`profile` проверяет полные повороты на двух разрешениях, со стартовой позиции и вплотную к порталу. Измеряются CPU, GPU, заполненные пиксели, рост пула и выделения буферов после прогрева.

`profile:pacing` открывает отдельный Chrome и использует холст размером 1710 × 1107 CSS-пикселей при DPR 2. Профилировщик задаёт воспроизводимые повороты и ходьбу, чтобы замер рендера не зависел от доставки raw-событий и фокуса автоматизированного окна; нативный ввод проверяется отдельно браузерными тестами. Сравниваются порталы, цельные стены, скрытый HUD и разрешение 1×. GPU измеряется асинхронно, Chrome trace сохраняется в `test-results/profiling/chrome-pacing.json`. Флаг Fullscreen API в автоматизированном Chrome не всегда меняет размер системного окна, поэтому размер холста задаётся явно. Эти замеры не заменяют проверку на экране пользователя.

### Материалы и освещение

Сохранены жёлтые обои и бежевый коротковорсовый ковролин. Текстура обоев подготовлена для обычного бесшовного повтора: разрывы орнамента исправлены после циклического сдвига на полтайла, края согласованы в самом PNG; исходный средний цвет восстановлен в линейном RGB. Крупные повторяющиеся пятна яркости выровнены частотным разделением в логарифмическом линейном RGB; тонкие линии, орнамент и зерно сохранены. Дополнительной обработки стыков и яркости во время игры нет. При загрузке из них оцениваются отдельные линейные карты нормалей 1024² и шероховатости 512². Градиенты мелкой фактуры задают сдержанный рельеф: 0,65 мм для обоев и 3 мм для ворса. Цвет, нормали и шероховатость используют обычное повторение без зеркальных отражений. При вычислении рельефа градиенты проходят через границу тайла, сохраняя периодическую выборку. У ковролина высокая шероховатость и слабый мягкий блеск волокон (sheen). Блики и блеск ковролина берутся из общего окружения комнат; направленные источники дают рассеянный свет и динамические тени. Это сохраняет непрерывность блеска при наклонном взгляде через проход, где локальные точечные блики иначе обрывались. Пьедесталы и чаши лунок сделаны из матового бетона с мелкими порами. К собственному цвету бетона применяется 50% прежней бежевой тонировки в сторону #cdbb86; фактура сохраняется множителем материала в линейном RGB. Внутренняя поверхность лунок имеет тот же базовый цвет, что и пьедестал, без дополнительного затемнения материала. Карта цвета бетона хранится в JPG, исходный масштаб — 0,8 м на тайл; из неё при загрузке оцениваются отдельные карты нормалей и шероховатости с рельефом 0,7 мм. Боковые грани пьедестала развёрнуты единой полосой по периметру с одинаковым направлением UV, без зеркального повтора на соседних гранях. Целое число тайлов замыкает полосу без дополнительного шва; горизонтальный масштаб слегка подстраивается под периметр, вертикальный сохраняется. Текстура лунок проецируется в координатах пьедестала. Цветовые карты читаются в sRGB без снижения насыщенности. Физический масштаб сохранён: обои — 1,2 м, ковролин — 1 м, потолок — 0,65 м. Потолок использует текстуру типичной офисной минеральной панели с мелкими порами и неровными прорезями, отдельные карты нормалей (рельеф 1,2 мм) и шероховатости. Тёплый серо-бежевый Т-профиль #c9c0ae шириной 24 мм, чуть темнее самой панели и без отдельной полоски по краю, добавляется к изображению при загрузке; свечение потолочного заполнения также модулируется фактурой, сохраняя тёмные поры. Фильтрация — линейная с mipmaps и анизотропией до 8×. Вход доступен после загрузки материалов, подготовки света и GPU.

Шары диаметром 8 см используют материал полированной смолы `MeshPhysicalMaterial`: неметаллическую поверхность с IOR 1,57, шероховатостью 0,137–0,169 и тонким глянцевым слоем. Общая линейная карта 256² задаёт едва заметную неоднородность полировки, без зерна в цвете. Геометрия общей сферы — 64 × 48 сегментов. Отдельная резкая PMREM-карта с гранями 256 пикселей снимается из фактического центра установленного шара в стартовой комнате после подготовки материалов и света. Это включает в нижнюю часть отражения затенённую лунку; съёмка над центром пьедестала ошибочно подставляла яркий бетон и создавала светлую кайму снизу. Она содержит настоящие текстуры, освещение и геометрию потолка, стен и пьедестала; яркость рассеивателей в HDR-снимке поднята для белых отражений полированной смолы, а вклад поверхностей архитектуры приглушён до 28%, чтобы стены и пьедестал не высветляли нижнюю часть шаров. В снимке виден только рассеиватель над пьедесталом исходного шара: остальные панели скрываются на время съёмки, поскольку общая карта не может правильно разместить их отражения у всех лунок. Их источники света продолжают освещать комнату; после съёмки все панели снова видимы. Сами шары и экранные изображения порталов в снимок не попадают. Блики смолы и глянцевого слоя берутся только из карты отражений: направленные источники освещают шары и дают тени, но не добавляют дублирующие круглые блики поверх отражений панелей. Это общее приближение локального окружения для всех шаров; карта готовится один раз при запуске и не пересчитывается при поворотах, переходах или перестановке шаров. Новых источников света и проходов рендера во время игры нет.

В занятой лунке живой прямой свет каждой потолочной лампы проверяется точным пересечением луча со сферой. Карта теней комнаты продолжает учитывать остальные препятствия. У 8-сантиметрового шара обратная глубина в низком разрешении пропускала свет у чаши, а лицевая давала самозатенение на сфере; точная локальная проверка устраняет светлую полоску бетона без изменения материала или добавления тёмной каймы. Запечённый прямой свет дополнительно перекрывается аналитической тенью сферы от потолочной панели. Размер полутени зависит от размера рассеивателя и расстояния до шара. Контактное затенение по зазору между чашей и сферой ослабляет отражённый и окружающий свет у места касания. Наличие шара передаётся одним байтом на вершину чаши; обновляется только изменившаяся лунка, без новых проходов рендера и пересчёта карт света. Пустая лунка сохраняет равномерный базовый оттенок. Проверка сравнивает реальные пиксели чаши с тенью и без неё, а также первый и последующие кадры после взятия и установки шара.

Пьедесталы и светильники привязаны к общей сетке потолочных тайлов **65 × 65 см**, по размеру квадратного пьедестала. Обычно начало координат комнаты совпадает с центром тайла; центры остальных тайлов имеют координаты, кратные 65 см. В Y-комнате пульты стоят точно на центральных осях боковых коридоров: X = ±2,6 м, Z = 2,6 / √3 м. Начало потолочной сетки в этой комнате сдвинуто по Z к пультам, чтобы светильники оставались над ними и в центрах тайлов. При загрузке конфигурации положения пультов округляются к ближайшим центрам тайлов с сохранением симметрии. Текстура потолка использует тот же размер и смещение сетки; светящаяся часть имеет размер 62,6 × 62,6 см и заполняет весь просвет между профилями потолочной сетки, без полоски фактуры панели вокруг. Ширина профиля и размер рассеивателя связаны общей константой.

В каждой комнате над каждым пультом расположен один светильник: в A, D и Y — по два, в B, C и + — по одному, в H — семь. Всего 16 светильников. Один общий список положений используется для видимых панелей, источников, запечённого света, переноса через проходы и отражений. У каждого свой направленный вниз источник в центре панели и своя карта теней 1024². 55% статической рассеянной составляющей интегрируется по девяти точкам фактической панели 62,6 × 62,6 см; оставшиеся 45% сохраняют динамические тени шаров и прямые блики отделки; у шаров блики формируются только отражениями видимых панелей. Рассеиватель имеет мягкий рисунок трубок и призматическую фактуру. Интенсивность источников — 25. Дальность — 20 м; в хабе у четырёх светильников в тупиках — 15 м, у трёх в центральном ряду над пультами B, E и G — 5 м. Дальность каждой панели учитывается в прямом и отражённом свете и при переносе через проходы. Затухание плавное; свет убывает с квадратом расстояния. Яркие участки под панелями отделены от затемнённых углов. Заполняющий свет приглушён: HemisphereLight — 0,24, AmbientLight — 0,016, интенсивность окружения — 0,12. При изменении видимости шара или стены пересчитываются только карты источников, чей световой конус пересекает изменившийся объект. Выбор цвета шара и повторная синхронизация не требуют пересчёта. Карты переиспользуются во всех рекурсивных видах. При изменении объекта очищается и перерисовывается только его консервативная проекция в карте, включая запас в три текселя; остальные пиксели сохраняются. Проекция стен обрезается ближней плоскостью теневой камеры, пересекающиеся изменения объединяются до рендера. Принудительный полный пересчёт и первоначальная подготовка сохраняют полную область карты. В проверке действия с шаром это около 2 тысяч пикселей вместо нескольких миллионов. После основного рендера подготавливается не более одной оставшейся карты невидимых комнат за кадр: работа распределяется заранее, а не откладывается целиком до входа в изменённую комнату.

Одно отражение рассеянного света интегрируется по площади пола и стен: поверхности разбиты на ячейки не крупнее 62,5 см, каждая получает собственную освещённость от девяти точек потолочных панелей. Пограничные ячейки пола обрезаются по реальному контуру, включая наклонные стены и вырезы сложных комнат. Части ячеек с центром за стеной сохраняются, если их площадь попадает внутрь комнаты: вдоль границы нет зазоров и выступающих отражателей. Внутренние прямоугольные ячейки сохраняют прежнюю сетку. Видимость каждой ячейки проверяется отдельно по стенам и реальным силуэтам пьедесталов. Поэтому перекрытие небольшой части отражающей поверхности больше не выключает вклад целой площадки 2,5 м и не образует широкую полосу на стене. Вблизи ячейки её вклад определяется проекцией телесного угла многоугольника на полусферу приёма; вдали используется квадратура с косинусами и квадратом расстояния, с плавным переходом между оценками. Проёмы исключены из отражающих площадей по точным размерам; надпроёмная часть стены сохраняет отражение. Площадки остаются на настоящих плоскостях стен, а угловые получатели оценивают внутренний предел освещённости — смещение отражателя внутрь комнаты не создаёт тёмную кайму. Консервативные проверки целых групп пропускают индивидуальные лучи только при гарантированно свободном пути. Учитываются стены, вырезы сложных комнат и силуэты пьедесталов. Потолок тоже получает это отражение: его видимая внутренняя сторона включена в карту с шагом 50 см, достаточным для мягкого рассеянного света. Скрытое перекрытие потолка со стенами продолжает внутреннюю освещённость без чёрной каймы. Прямого излучения вверх панели не добавляют. Участки потенциальных дверей не служат отражающими источниками. Прямой свет панели и цветное отражение упакованы в одну RGBA half-float карту на комнату; семь карт занимают 1,75 МиБ. Они готовятся единожды при запуске и во время игры требуют одной дополнительной выборки текстуры, без новых проходов или источников. Это одно отражение с усреднёнными цветами материалов, не полная трассировка глобального освещения.

Стенки стыкуются по точному контуру комнаты со скошенным в плане наружным стыком: скрытых продолжений внутренних плоскостей за углом нет. Наружные грани и скрытые торцы не занимают карты света. Защитные тексели у углов получают освещённость настоящего края стены, поэтому в пяти- и шестиугольнике не образуются вертикальные тёмные полосы. Собственная половина порога и откосов получает свет комнаты до плоскости портала; боковые стенки и перемычка продолжают перекрывать лучи. Граничные пробы света учитывают округление float32: точка на краю проёма не должна ошибочно считаться находящейся за стеной. Браузерная проверка сравнивает освещённость пола в 261 точке по обе стороны проходов всех семи форм, включая точки в 5 мм от откосов, с допуском два уровня из 255.

Мягкие отражения тёплой комнаты рассчитываются один раз в PMREM 128² и используются всеми комнатами с небольшой интенсивностью. Они помогают читать форму шаров и свойства отделки; точного зеркального отражения текущих проходов и предметов нет. Контактное затемнение ослабляет и отражённые блики, чтобы они не засвечивали основание пьедестала.

Через открытый проход прямой свет соседних потолочных панелей рассчитывается отдельно от мягкого отражённого света. Положения источников преобразуются через портал; границы лучей проверяются по обеим граням проёма в стене толщиной 30 см при заполнении подробных карт. Силуэты стен и пьедесталов обеих комнат растеризуются в отдельный атлас глубины 2048²: до 28 участков 256 × 512 для четырёх направленных концов проходов. Камеры ограничены областью проёма и небольшим участком вокруг него, поэтому разрешение расходуется на полезные лучи. Атлас цвета RGBA8 занимает 16 МиБ, дополнительно используется буфер глубины. Четыре выборки PCF смягчают только мелкий пиксельный край; сравнение глубины учитывает наклон принимающей поверхности. Все геометрии, материалы и GPU-ресурсы прогреваются перед игрой. Атлас обновляется синхронно при изменении соединений, до первого обычного кадра; ходьба, повороты и выбор цвета его не меняют. Источники движка и дополнительные проходы обычного кадра не добавляются. Результат проекций записывается на GPU в отдельные одноканальные half-float карты поверхностей с шагом 2,5 см и шагом 1,25 см у проходов. Семь R16F-карт занимают 24 МиБ. Они обновляются вместе с глубиной только при изменении соединений; обычный кадр читает готовую освещённость одной билинейной выборкой. Это устраняет дорогостоящий цикл источников из основного PBR-шейдера. Карты и геометрия для их заполнения выделяются и прогреваются заранее, включая изначально неактивные проходы. Повторяющиеся шары и чаши при заполнении используют сетку, соответствующую их небольшим световым картам, без дублирования полной геометрии.

Полутень от проёма определяется долей видимой площади настоящей квадратной панели, с учётом её поворота через портал. Из каждой точки принимающей поверхности панель обрезается ограничениями двух граней стены толщиной 30 см; площадь оставшегося выпуклого многоугольника даёт плавную видимость. У косяка переход узкий, дальше от него расширяется пропорционально геометрии. Край не размывается одинаковым фильтром и не разбивается на полосы от нескольких дискретных источников. При заполнении атласа глубины соединённые стены исключаются: их центральная жёсткая тень иначе обрезала бы эту полутень. Прочие стены и пьедесталы сохраняют проверку по картам глубины. Расчёт силы излучения и затухания использует центр панели с прежним соотношением направленного и косинусного излучения; это приближение освещённости протяжённого источника. Новых GPU-карт и дополнительных проходов обычного кадра нет. Мелкие тени 8-сантиметровых шаров остаются в локальном освещении.

Области записи в GPU-карты задаются в физических текселях render target, независимо от масштаба экрана. Проверки сравнивают карты глубины и освещённости петли квадратной комнаты при DPR 1 и 1,5: их содержимое должно совпадать. Это предотвращает смещение участков атласа и пятнистые тени на Retina.

Внутри порога обе комнаты используют одни и те же участки атласа глубины для света с обеих сторон. К 60 см от границы собственный свет плавно переходит в обычное локальное освещение. Это сохраняет непрерывность на стыке без восстановления резких теней из сетки 25 см. Цветное отражение использует ту же площадную квадратуру, что и внутри комнаты: полный вклад в первых 0,5 м от границы, плавное затухание к 2 м. Свет не распространяется дальше через цепочку проходов.

При сборке мягкое отражение для всех **812 направленных соединений** между 29 местами проходов рассчитывается как **2D-карты поверхностей**. Геометрия для игры и расчёта создаётся одной функцией. Плоские грани группируются по плоскости и нормали и получают карту с шагом 25 см; одинаковые плоскости открытой и закрытой стены, пола и порогов используют общие координаты. У шаров и чаш отдельные небольшие карты 8 × 6 отсчётов с учётом кривых нормалей. Мелкие чаши оцениваются на высоте края, поскольку диффузная модель препятствий использует сплошные силуэты пьедесталов. Тонкие внутренние стенки лунок не получают отдельного перенесённого света. Обычное освещение и динамические тени сохраняются. Участки карт имеют по одному защитному текселю; при расчёте край растягивается на соседние тексели, чтобы фильтрация не создавала тёмных полос и не смешивала разные поверхности. Повторяющиеся шары и чаши сохраняют общие буферы вершин и индексов; индивидуальны только дополнительные UV.

На полу карты собственного и перенесённого света читаются кубическим B-сплайном: плавная реконструкция по 16 соседним текселям выполняется четырьмя аппаратными билинейными выборками. Это сглаживает мягкую составляющую света; резкие тени прямого переноса теперь используют отдельный атлас глубины. Положительные веса сохраняют неотрицательную освещённость и не создают светлых ореолов. Краевой ряд проб прохода расположен на 10 см за плоскостью перехода, в соседней половине общей стены. Его свет вычисляется в реальной позиции вместо повторения значения на границе: обе комнаты реконструируют один и тот же градиент, без небольшого скачка яркости. Проверка видимости таких проб учитывает полную толщину открытого прохода 30 см, сохраняя блокировку боковыми откосами. Текстуры ковролина, нормали, разрешение рендера и обычные карты теней фильтруются как прежде; размеры атласов мягкого света не меняются.

В собственной карте R хранит прямую освещённость панели, GBA — цветное отражение; в картах переноса используется только GBA, уже для известной нормали поверхности. Косинус приёма вычисляется по полному скалярному произведению, включая наклонные стены многоугольников. Объёмных решёток в воздухе и шестиканальных текстур нет. При сборке Node.js создаёт геометрию для расчёта, растеризует поверхности и вычисляет все связи. Сам расчёт занимает около **25 секунд в одном процессе** на текущей машине. Результат сохраняется без потери точности: панели используют half-float, значения переноса — float32, диапазоны ненулевых данных — uint32. Ненулевые значения уплотняются отдельно по каналам, вклады меньше 0,0005 исключаются тем же алгоритмом. Файл для текущего уровня занимает около **7,17 МБ**, с gzip — **3,17 МБ**, с Brotli — **0,94 МБ**. Кэш определяется хешем всех транзитивных локальных импортов скрипта расчёта, самого генератора, версии Node.js и файлов зависимостей. Новые импортированные модули автоматически включаются в проверку. Правка во время расчёта повторно проверяет хеш перед публикацией результата. Имя файла содержит эту ревизию; загрузчик проверяет её, размеры карт и все 812 соединений. Массивы читаются прямо из загруженного буфера. Ошибка загрузки или несовместимый файл оставляют вход отключённым и показывают сообщение. Во время игры CPU-заданий расчёта света нет.

В `dist/assets/` сборка записывает бинарный файл и сжатые варианты `.br` и `.gz`. `npm run dev` и `npm run preview` автоматически выбирают Brotli или gzip по `Accept-Encoding` и отдают правильный `Content-Encoding`; файлы с хешем разрешено кэшировать на год. При публикации на другом статическом сервере нужно включить такую же отдачу готовых сжатых вариантов (либо HTTP-сжатие бинарного файла); без неё браузер загрузит исходные 7,17 МБ. Файл уже содержит все данные света для возможных соединений. Загрузка текстур, компиляция шейдеров, начальные карты теней, подробный прямой свет и отражения шаров по-прежнему подготавливаются на GPU браузера.

Для каждой комнаты заранее выделены два сменных half-float 2D-буфера: новый свет записывается в запасной, а не в текстуру, которую GPU мог читать в предыдущем кадре. Атласы имеют размеры 128 × 128, 128 × 256 или 256 × 256; вместе **14 RGBA-текстур занимают 3,5 МиБ GPU-памяти**, ещё столько же занимают рабочие float32-буферы на CPU. Два последних сочетания переиспользуются без повторной загрузки. При действии с шаром складываются только ненулевые тексели готовых карт; свет и проход обновляются синхронно. Закрытие последнего прохода отключает карту без загрузки текстуры. Ходьба, повороты и выбор цвета карты не меняют. Обычная поверхность читает перенесённый свет одной 2D-выборкой; на полу каждая выборка карты света реконструируется четырьмя билинейными чтениями. Только в небольшой зоне у открытого прохода добавляются два таких чтения карт для согласованной освещённости. Отдельный атлас теней прямого переноса обновляется только при изменении соединений; параметры его расчёта хранятся в небольшой float-текстуре. Основной шейдер получает только готовую подробную освещённость. Число и размер GPU-текстур во время игры постоянны. `profile:lighting` сравнивает включённый и отключённый перенос в порядке ABBA на одном холсте, включая хаб при 3840 × 2160; GPU-результаты читаются асинхронно.

Предыдущий объёмный вариант сравнивался с картами в 43 ракурсах всех комнат, включая рекурсивные виды, пол у входов и два одновременных вклада света. Средняя разница каждого кадра — не более 0,16 уровня из 255, максимальная локальная разница — 12. Это смена приближённой модели интерполяции, поэтому побитового совпадения с объёмным вариантом нет. Скрипт `node scripts/compare-surface-lighting.mjs --capture` сохраняет текущие эталоны в `/tmp/samewhere-lighting-reference`, повторный запуск без `--capture` сравнивает их с новой реализацией. `--image=10` сохраняет пару изображений для визуальной проверки. Путь можно задать через `--directory=/absolute/path`.

До включения кнопки входа компилируются варианты шейдеров для основного экрана и порталов, загружается геометрия всех семи комнат, включая закрытые/открытые стены и пустые лунки, подготавливаются буферы порталов и рассчитываются все 20 начальных карт теней. Каждый вариант также проходит реальную отрисовку в линейный MSAA-буфер с тем же числом сэмплов, что у порталов, и в sRGB-холст с его сглаживанием: одной компиляции GLSL недостаточно, драйвер может отложить подготовку графического конвейера до первого использования. Прогрев холста ограничен небольшим участком 64 × 64 CSS-пикселя. Отдельно выполняется чтение полей перенесённого света, включая комнаты без активного прохода, и повторная загрузка уже использованной 2D-карты. Завершение GPU-подготовки проверяется асинхронным fence без блокирующего чтения. Неподвижная архитектура для теневого прохода объединяется в одну геометрию на комнату. Корпуса пьедесталов и лунки сохраняют исходные меши и координаты: для их лицевых теней это исключает погрешности самозатенения от округления мировых координат в объединённом буфере. Изменяемые стены и шары также рисуются отдельно. Основная геометрия для изображения и выбора лунок сохраняется. Матрицы неподвижных объектов рассчитываются заранее. Загрузка меню может занять немного больше времени, зато первая встреча с комнатой не требует подготовки её ресурсов. После каждого прогрева основного холста областью 64 × 64 в той же задаче восстанавливается полный обычный кадр комнаты: временная отрисовка не попадает в показ. По завершении подготовки ещё один полный кадр рисуется до включения кнопки входа. Это исключает чёрную вспышку при применении карт и прогреве конвейера; браузерная проверка отслеживает основной холст на каждом этапе подготовки.

Контактное затенение достигает 20% у основания пьедесталов, 10% вдоль их вертикальных рёбер и на стыках стен с полом и потолком и 5% в вертикальных внутренних углах стен. Для всех стыков сохраняется экспоненциальный спад с характерной длиной 10 см (1 / CONTACT_FALLOFF) в линейном свете. Выбирается более сильное затенение, без накопления нескольких полос в углах; одинаково ослабляются рассеянный свет, блики и имитирующее фоновый свет свечение потолка. На полу затенение следует реальным отрезкам стен и силуэтам пьедесталов. На стенах тот же профиль действует вдоль вертикальных внутренних углов комнаты; выпирающие углы сложных комнат не затемняются. Расстояния до концов стены задаются в геометрии и интерполируются без дополнительных карт или расчёта света. При открытии прохода полоса под стеной исчезает в том же кадре, а контакт продолжается вдоль боковых косяков до плоскости портала. Низ пьедестала слегка заглублён в ковролин. Для корпусов и блюдец карта теней записывает ближайшую к источнику лицевую поверхность. Обратные грани корпуса лежат ниже пола, а односторонние блюдца при таком отсечении исчезают: сглаживание прежней карты могло пропускать свет у основания. Исправляется сама глубина тени, без дополнительной тёмной каймы на стыке. На корпусах пьедесталов каждая выборка PCF сравнивается с глубиной плоскости грани в центре выбранного текселя, а не с одной глубиной исходного фрагмента. Наклон плоскости вычисляется в вершинном шейдере по проекции геометрических касательных. Это устраняет горизонтальные полосы самозатенения при боковом свете; реальные тени от других предметов сохраняются. Размер карт, число выборок и проходов рендера не меняются; тени на полу продолжают использовать прежнее сравнение глубины. Рассеянный свет и контактное затенение имитируют отражения и тесные стыки поверхностей. Все цветовые вычисления и дальнее затухание выполняются в линейном пространстве, перевод в sRGB — при выводе.

Расчёт контакта каждого пьедестала ограничен его окрестностью: за её пределами остаточное экспоненциальное затенение визуально пренебрежимо. Особенно это сокращает работу пола H с семью разными силуэтами. Для локальных источников пропускаются выборки теней и BRDF, если свет вне конуса или направлен за поверхность: их вклад там равен нулю. Bump-нормали учитываются до этой проверки. Разрешение порталов, сглаживание, источники и качество карт теней сохраняются. Браузерная проверка сравнивает оптимизированные и исходные вычисления в 68 ракурсах всех комнат, включая оба вида у четырёх входов H. Частичные теневые обновления отдельно сравниваются с полным рендером исходных мешей в 126 состояниях и ракурсах, включая открытые и закрытые стены вблизи; разрешено не более одного уровня цвета из 255. Первый кадр после перестановки шаров сравнивается с последующими: запоздалого изменения света быть не должно. `profile:hub` измеряет первое открытие прохода и переход в хаб при 2565 × 1660 и 3840 × 2160; флаг `--reference` отключает сокращение вычислений для сравнения на том же маршруте. Флаг `--reconnect` добавляет серию открытий, закрытий и смены входа H; `--full-shadows` отключает частичное обновление карт для сравнения нагрузки. В отчёте есть площадь обновлённых карт, немедленная готовность света и число фоновых заданий после начала игры (должно быть нулевым).

Высота пьедесталов — **1,20 м**, расстояние от центра до стороны обычного многоугольного пьедестала — **32,5 см** (квадратный пьедестал имеет основание 65 × 65 см). Два пульта внутри треугольной комнаты расположены симметрично относительно центра на биссектрисе угла: X = 0, Z = ±1,95 м. Пульты Y, + и H воспроизводят комнату в масштабе 0,06: самый длинный размер + и H — 84 см. Диаметр шаров — **8 см**. Центры всех лунок находятся в **9 см от ближайшего края**; на обычных многоугольниках это 23,5 см от центра. Лунки — закрытые блюдцеобразные чаши диаметром **10 см** и глубиной **1,625 см**, опущенные на **0,5 см** относительно поверхности пьедестала. Короткая вертикальная стенка соединяет край чаши с поверхностью; полная глубина лунки — **2,125 см**. Материал и базовый цвет всей внутренней поверхности лунок, включая вертикальные стенки, совпадают с пьедесталом; дополнительной тонировки нет. Освещение и тени шаров сохраняются. Нижняя точка шара совпадает с дном чаши в центре; радиус кривизны дна больше радиуса шара. Наружная поверхность пьедестала — единая призма без шва между верхней и нижней частями. Кромки остаются острыми, без фасок и скруглений.

### Движение и восстановление

Высота глаз фиксирована на 1,65 м, радиус игрока — 0,22 м, скорость ходьбы — 5 м/с. Перемещение разбивается на шаги до 6,5 см; после перехода остаток перемещения преобразуется и продолжается в новой системе координат. Нет искусственной задержки портала, поэтому можно сразу шагнуть назад.

В A–D стены проверяются как полуплоскости выпуклого многоугольника; в Y, + и H — как конечные сегменты контура с учётом радиуса игрока и открытых проходов. Поэтому внутренние углы не перекрывают соседние ветви и не позволяют пересекать пустоты между коридорами. Пьедесталы проверяются как окружности по описанному радиусу их формы. Внутри толщины прохода боковые коллизии останавливают движение у откоса без выталкивания обратно в комнату. Луч взаимодействия учитывает реальную видимую геометрию стен и пультов.

История ограничена 256 значимыми действиями. Снимок перед переходом сохраняет безопасную позицию внутри исходной комнаты. Отмена восстанавливает шары, комнату, позу и выбранный цвет.

## Приёмочные проверки

Логические тесты проверяют начальные связи, подбор и размещение, отсутствие обмена, сохранность четырёх шаров при 2 000 действиях, 841 комбинацию преобразований между всеми 29 местами проходов, коллизии, обратный шаг, отмену и 100 переходов без дрейфа. Отдельно проверяются равные ветви Y, доступность всех концов + и H, непроходимость вырезов, обратные переходы через все торцы и отступы лунок от края миниатюр. Перебор на уровне комнат проверяет проходимость участка до G и исключает решение с постоянными переходами через A или сохранением одной из исходных связей после D.

Отдельно проверяются прохождение 30 см между внутренними гранями стен, обратный путь, боковые коллизии внутри проёма, реальная толщина геометрии стен и их половин, отсутствие линий-контуров и загрузка текстур без внешних запросов.

Тесты ввода проверяют сохранение полного перемещения на частотах 30–144 кадра/с, остановку без дрейфа и очистку накопленного движения.

Браузерные тесты проверяют реальные клики по лункам, общие изображения пультов, отсутствие переключателя режимов и реакции на F2, полный маршрут из A через D до G ходьбой и кликами, доступность всех лунок и размещение шаров на каждом из семи пультов хаба, переходы между всеми семью формами, стабильность GPU-ресурсов после 100 циклов. Сравниваются WebGL-кадры за 1 мм до и после границы каждого типа перехода. Дополнительно весь кадр проверяется на расстоянии 0,01 мм и непосредственно на плоскости перехода: оба направления, поворот взгляда, смещение к откосу и обратный ход.

Цветовая проверка подтверждает сохранение насыщенности вблизи, плавное затемнение на 48–68 м и чёрный цвет за пределом видимости; результат сравнивается напрямую и через портал. Лучи изнутри каждой лунки проверяют все четыре направления и закрытое дно. Отдельно проверяются число светильников, их совпадение с положениями пультов и источников теней, размеры рамок и линз. Лучи в фактическую геометрию потолка подтверждают, что центры панелей попадают в центры тайлов текстуры, а все четыре угла рамок — в узлы сетки.

На Retina проверяется однопиксельная шахматная сетка: вид через портал должен сохранять тот же контраст и совпадать с прямым видом, в том числе после изменения размера окна. Обрезанные буферы дополнительно сравниваются с полноэкранными при поворотах в обеих комнатах.

Нативный захват мыши проверяется через Chrome: сумма относительных событий совпадает с итоговым углом, совместимые `mousemove` не дублируют raw-события, объединённые отсчёты учитываются один раз, а F4 возвращает исходный взгляд даже после движения мышью во время проверки.

## Ограничения первой версии

- Только настольное управление, без прыжков, физики предметов и сохранения между запусками.
- Выбирать предметы можно только в текущей комнате. Изображения в проёмах интерактивными не являются.
- Дальность 68 м, предел рекурсии 10 переходов и бюджет 32 прохода фиксированы; дальние поверхности плавно затухают до чёрного.
- Коллизия пьедестала использует консервативную окружность, а не точную форму его основания.
- Освещение использует PBR-материалы, площадной рассеянный свет панелей, одно приближённое отражение света, общую PMREM-карту архитектуры, отдельную карту отражений полированных шаров и кэшированные динамические тени. Отражения приближённые; полной трассировки глобального освещения и динамических кубических камер нет. Цветовые текстуры обоев и ковролина сохраняют разрешение 1254²; бетон пьедесталов и минеральные потолочные панели хранятся в JPG 1254². Сетка потолка добавляется при загрузке, карты нормалей и шероховатости рассчитываются отдельно.
- Инструменты проверки состояния `window.__samewhere` доступны только в режиме Vite dev и удаляются из production-сборки.

Следующие комнаты, формы и положения пультов можно добавлять через конфигурации `ROOMS`; правила шаров и портальные преобразования уже отделены от отображения.
